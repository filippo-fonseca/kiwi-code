# What changed from t3code

This file is the canonical, exhaustive record of everything Kiwi Code changed
from upstream (`pingdotgg/t3code`): every upstream-owned file we modify and why,
plus the new Kiwi-only code we added on top. It is the map used during each
weekly `git merge upstream/main` to know exactly where and why we differ, and it
is organized by the milestones that produced the changes (Phase 0 rebrand, the
product-name copy pass, the Phase 1 bgsd-observability layer, the visible-brand
sweep, and standalone fixes).

**Every Kiwi Code PR MUST keep this document current.** If a PR touches a file
that upstream owns, add or update its row here in the same PR. If a PR stops
diverging on a file (for example, upstream adopts our change), remove its row. A
PR that changes upstream files without updating this document is incomplete. The
same rule is wired into `AGENTS.md` / `CLAUDE.md`.

## Change history at a glance

- **Phase 0 (rebrand):** renamed the app's identity from "T3 Code" to "Kiwi Code"
  across the branding constants, the browser shell title and splash, the desktop
  display name, the packaged bundle `appId`, and the auto-update feed.
- **Product-name copy pass:** renamed the in-prose `"T3 Code"` product-name
  literal to `"Kiwi Code"` across ~45 user-facing strings in `apps/web/src` and
  `apps/desktop/src`, plus the tests that assert them.
- **Phase 1 (bgsd observability):** added the Kiwi-only bgsd contracts, server
  service, streaming RPC, and web dashboard/sidebar/status-bar UI, with a minimal
  set of upstream touchpoints to wire them in.
- **Visible-brand sweep:** replaced the T3 wordmark/icon assets with a Kiwi mark,
  swapped the in-app sidebar wordmark, renamed the visible "T3 Connect" service
  label to "Kiwi Connect" and the "T3 Server" copy to "Kiwi Code server", and
  renamed this document from `KIWI-DIVERGENCE.md` to `WHAT_CHANGED_FROM_T3.md`.
- **Fixes:** the issue #7 port-scanner fix (currently on the PR #8 branch, not yet
  merged to the fork mainline).

## Deliberately NOT changed (documented decisions)

- **App id / bundle id at runtime (`com.t3tools.t3code`).** The macOS/Windows/Linux
  runtime bundle identifiers in `apps/desktop/src/app/DesktopEnvironment.ts`
  (`appUserModelId`, `linuxDesktopEntryName`, `linuxWmClass`) and in
  `apps/desktop/scripts/electron-launcher.mjs` (`APP_BUNDLE_ID`,
  `APP_PROTOCOL_SCHEMES` such as `t3code`) were left as-is. These are protocol
  handlers, OS registration identifiers, and deep-link schemes. Changing them
  risks breaking dev-mode launch, deep links, and single-instance behavior, and
  they are internal identifiers rather than user-visible product name. Only the
  packaged build `appId` (in `build-desktop-artifact.ts`, which is what ships to
  end users) was rebranded to `com.filippofonseca.kiwicode`. Aligning the runtime
  identifiers and protocol schemes is deferred to a later phase.
- **userData directory names (`t3code`, `t3code-dev`, and legacy `T3 Code (Alpha)`).**
  `userDataDirName` / `legacyUserDataDirName` in `DesktopEnvironment.ts` were left
  unchanged. Renaming the userData directory would orphan any existing user
  settings/state and there is legacy-path migration logic keyed on these names.
  This is a state-migration concern, not a simple config change, so it is deferred.
- **Environment variable prefixes (`T3CODE_*`) and telemetry/span keys**
  (for example `desktop.appIdentity.configure`, `t3codeCommitHash`,
  `@t3tools/desktop/...` service tags). Left unchanged: these are internal
  contract keys, config env names, and observability identifiers. Renaming them
  would break configuration and telemetry continuity with no user-facing benefit.
- **The `[t3-connect]` log prefix and `T3ConnectSidebar*` component identifiers.**
  The visible `"T3 Connect"` label was renamed to `"Kiwi Connect"` in the
  visible-brand sweep (see the table above), but the `console.error("[t3-connect] …")`
  log prefix and the `T3ConnectSidebarSignIn` / `T3ConnectSidebarAvatar` component
  and symbol names were left as-is. They are code identifiers and log-search keys,
  not user-visible text, and renaming them has no user-facing benefit.
- **Legacy userData directory literal `"T3 Code (Alpha)"` / `"T3 Code (Dev)"`.**
  `legacyUserDataDirName` in `DesktopEnvironment.ts` (and the test fixtures that
  assert the legacy migration path) keep the old `T3 Code` literal. It is a
  state-migration key that must match the directory an existing install already
  wrote; renaming it would orphan user state. This is covered by the userData
  bullet above and is intentionally out of scope for the visible rebrand.

## Pending

- **`assets/` marketing/marketing-adjacent images.** The visible-brand sweep
  rebranded the app's own served icons and the desktop icon set (see the
  visible-brand-sweep table), but any remaining upstream-authored images under
  `assets/` (marketing art, screenshots) were not re-created and may still carry
  upstream branding. They are not part of the running app's UI and are deferred.
- **`.ico` fidelity on Windows.** The regenerated `favicon.ico` /
  `apps/desktop/resources/icon.ico` are valid PNG-compressed multi-frame icons
  written by a small in-repo packer (no `to-ico`/ImageMagick dependency was
  installed). They render correctly, but were not validated on a real Windows
  build; a Windows packaging pass should confirm the taskbar/installer icon.
